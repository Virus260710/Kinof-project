# Authentication — Adaptive (Face หลัก + OTP สำรองจากเว็บ)

## แนวคิด

| กรณี | การทำงาน |
|------|----------|
| **สแกนหน้าผ่าน** | เข้าได้เลย → ตรวจสิทธิ์ (schedule/booking) → ได้ที่นั่ง |
| **สแกนไม่ผ่าน / ระบบมีปัญหา** | ใช้ OTP ที่**ขอจากเว็บ** → กรอกที่ Kiosk → ตรวจสิทธิ์ → ได้ที่นั่ง |

> ไม่บังคับ OTP ทุกครั้ง — OTP เป็นทางสำรองเมื่อ Face ใช้ไม่ได้

---

## Flow หลัก — ทุกกลุ่ม (ที่ Kiosk)

```
มาที่ Kiosk หน้าห้อง Lab
    ↓
[1] สแกนใบหน้า
    ↓
    ├─ ผ่าน (confidence สูง) ──────────────────────┐
    │                                               ↓
    └─ ไม่ผ่าน / กล้อง error / Face Service down   │
           ↓                                        │
       แสดง "ใช้รหัสสำรองจากเว็บ"                   │
           ↓                                        │
       กรอก OTP 6 หลัก (ที่ขอจากเว็บไว้แล้ว)       │
           ↓                                        │
       Verify OTP ──────────────────────────────────┤
                                                    ↓
                              [2] ตรวจสิทธิ์ (Schedule หรือ Booking)
                                                    ↓
                              ├─ มีสิทธิ์ → ได้ห้อง + เลขที่นั่ง → เข้าใช้
                              └─ ไม่มีสิทธิ์ → ปฏิเสธ
                                                    ↓
                              [3] Agent บันทึก log (auth_method: face | otp_fallback)
```

## Flow ขอ OTP จากเว็บ (ทำก่อนไป Lab — เผื่อสำรอง)

```
Login เว็บ (มือถือ/PC)
    ↓
กด "ขอรหัสเข้าห้อง" (เลือกห้องได้)
    ↓
ได้ OTP 6 หลัก — ใช้ได้ 10 นาที, ครั้งเดียว
    ↓
เก็บไว้ → ถ้า Kiosk สแกนหน้าไม่ผ่าน → กรอก OTP ที่เครื่อง
```

**แนะนำ UX:** แสดง countdown บนเว็บ + ข้อความ "ใช้เมื่อสแกนหน้าไม่สำเร็จเท่านั้น"

## Flow ตามกลุ่ม (อัปเดต)

### กลุ่ม 1 — นักศึกษามีตารางเรียน

```
[ทุกครั้งที่เข้า]
1. มาหน้าห้อง Lab (ช่วงมีคาบ)
2. สแกนหน้า → ผ่าน → ตรวจตารางเรียน → ได้ที่นั่ง ✅
   (ถ้าไม่ผ่าน → OTP จากเว็บ → ตรวจตารางเรียน → ได้ที่นั่ง)
3. Agent log อัตโนมัติ
```

### กลุ่ม 2 — นักศึกษาไม่มีตารางเรียน

```
[ก่อน] Login เว็b → จอง (ห้อง/วัน/เวลา) → (optional) ขอ OTP สำรอง
[วันจอง] Kiosk → สแกนหน้า (หรือ OTP) → ตรวจ booking → ได้ที่นั่ง
```

### กลุ่ม 3 — บุคคลภายนอก

```
[ก่อน] ลงทะเบียน + ถ่ายหน้า (เว็บ) → จอง → (optional) ขอ OTP สำรอง
[วันจอง] Kiosk → สแกนหน้า (หรือ OTP) → ตรวจ booking → ได้ที่นั่ง
```

## คำแนะนำแต่ละส่วน

### Face Recognition
- threshold 0.5 ขึ้นไป = ผ่านทันที
- 0.4–0.5 (optional): ขอ OTP เพิ่ม — ป้องกัน false positive
- ต่ำกว่า 0.4 = ไม่ผ่าน → ใช้ OTP fallback

### Web (ขอ OTP)
- ต้อง login ก่อนขอ OTP
- OTP ผูก user_id + room_id (optional)
- แสดงเวลาหมดอายุ countdown
- Rate limit: 3 ครั้ง/ชม.

### Kiosk
- ลองสแกนหน้าก่อนเสมอ (3 ครั้ง max แล้วแนะนำ OTP)
- ปุ่ม "ใช้รหัสสำรองจากเว็บ" ไม่เด่นเกินไป (กัน abuse)
- แสดงผลชัด: ห้อง + เลขที่นั่ง หลังผ่าน

### Backend
- `access_logs.auth_method`: `face` | `otp_fallback`
- OTP เก็บ hash, one-time use, expire 10 min
- ตรวจสิทธิ์เหมือนกันทั้ง face และ OTP path

### Admin
- Report: สัดส่วน face vs otp_fallback
- Alert ถ้า otp_fallback > 30% (อาจมีปัญหากล้องหรือ abuse)

### Zenith Comp (โจทย์ 2 ชั้น)
- **ชั้น 1:** Password
- **ชั้น 2 (Login เว็b):** **Email OTP** — ดู [EMAIL_OTP.md](./EMAIL_OTP.md)
- **ชั้น 2 (Kiosk สำรอง):** Entry OTP ส่งทาง email เมื่อสแกนหน้าไม่ผ่าน

## เปรียบเทียบกับแบบเดิม

| | แบบเดิม | แบบใหม่ (Adaptive) |
|---|---------|-------------------|
| สแกนผ่าน | + กรอก OTP ทุกครั้ง | **เข้าได้เลย** |
| สแกนไม่ผ่าน | ติด — ไม่มีทาง | OTP จากเว็บ |
| UX | ช้ากว่า | เร็วกว่า |
| Security | สูงทุกครั้ง | สูงเมื่อจำเป็น + มี fallback |
