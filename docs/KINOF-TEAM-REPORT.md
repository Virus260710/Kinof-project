## 1. ปกและบทนำ

### KINOF คืออะไร

KINOF คือระบบจัดการห้องแล็บคอมพิวเตอร์แบบครบวงจร ใช้เมื่อห้องมีเครื่องจำนวนมาก นักศึกษาเข้าออกตามตารางเรียนหรือการจอง และผู้ดูแลต้องการเห็นว่าเครื่องไหนมีคนนั่ง ใครเข้าเว็บหรือโปรแกรมอะไร และคะแนนพฤติกรรมยังพอจองห้องได้หรือไม่

ระบบไม่ได้เป็นแค่เว็บจองห้อง แต่ประกอบด้วยสี่ส่วนที่ทำงานร่วมกัน:

1. **เว็บแอป** สำหรับนักศึกษาและผู้ดูแล (จองห้อง, เชิญเพื่อน, ขอรหัสฉุกเฉิน, ดูคะแนน, ตั้งค่าบล็อกเว็บ/โปรแกรม)
2. **เครื่องประตู (Kiosk)** สแกนใบหน้าหรือกรอกรหัสฉุกเฉิน เพื่อตรวจว่าคนนั้นมีสิทธิ์เดินเข้าห้องในช่วงเวลานั้นหรือไม่
3. **Windows Agent** บนเครื่องนั่งทำงาน ใช้ล็อกอินบัญชี KINOF เพื่อยึดที่นั่ง และบังคับนโยบายเว็บ/โปรแกรมบนเครื่องนั้น
4. **บริการใบหน้า (Face Service)** สร้างเวกเตอร์ใบหน้า 512 มิติ ใช้ตอนลงทะเบียนและตอนสแกนที่ประตู

### แก้ปัญหาอะไรในแล็บ

- จองห้องแล้วไม่รู้ว่ายังมีที่ว่างจริงกี่คน หรือจอง 1 คนแล้วทั้งห้องถูกมองว่าเต็ม
- คนไม่มีสิทธิ์เดินเข้าห้องได้ เพราะประตูไม่ได้ตรวจตารางเรียน/การจอง
- ที่นั่งถูกผูกผิดจังหวะ เช่น สแกนประตูแล้วระบบสุ่มเครื่องให้ ทั้งที่คนยังไม่ได้ไปนั่ง
- ผู้ดูแลไม่เห็นว่าเครื่องไหนมีคนนั่งจริง และบล็อกเว็บ/โปรแกรมไม่ได้บนเครื่องแล็บ
- คะแนนพฤติกรรมถูกหักมั่ว หรือถูกรีเซ็ตทุกครั้งที่เปิดเซิร์ฟเวอร์
- ใบหน้าคล้ายกันถูกจับเป็นคนผิด

นโยบายที่ล็อกแล้วในรอบนี้แยก **ประตู** กับ **ที่นั่ง** ให้ขาดจากกัน: ประตูตอบแค่ว่า “เข้าห้องได้หรือไม่ได้” ที่นั่งเป็น Occupied เมื่อล็อกอินบน Agent สำเร็จเท่านั้น

## 2. สถาปัตยกรรม

### แผนภาพข้อความของบริการ

```
นักศึกษา / แอดมิน (เบราว์เซอร์)
        │  http://localhost:5173
        ▼
 kinof-app  (React + Vite)
        │  JWT ใน Authorization
        ▼
 Kinof.Api  (ASP.NET Core 8)     http://localhost:5106
        │
        ├── SQLite  kinof.db     (users, bookings, seats, agents, …)
        │
        ├── Face Service         http://localhost:8001
        │     InsightFace buffalo_l → embedding 512 มิติ
        │     ไม่เก็บรูป
        │
        ├── เครื่องประตู Kiosk
        │     header X-Kiosk-Key  ผูกห้อง
        │     สแกนหน้า / OTP ฉุกเฉิน → เข้าห้องได้หรือไม่ได้
        │     ไม่จ่ายที่นั่ง
        │
        └── Windows Agent บนเครื่องแล็บ  (ต้อง Administrator)
              header X-Agent-Key  ผูกที่นั่ง
              ล็อกอิน KINOF → ที่นั่ง Occupied
              เขียน C:\Windows\System32\drivers\etc\hosts
              ช่วง # KINOF-BLOCK-START … # KINOF-BLOCK-END
              ปิด process ตาม program_blacklist
```

เวลาทั้งหมดแปลงเป็นกรุงเทพก่อนเทียบตารางเรียน โควตารหัสฉุกเฉิน และเดือนของคะแนนพฤติกรรม ฐานข้อมูลเก็บเวลาเป็น UTC แล้ว API ส่งออกให้เว็บเป็น ISO พร้อม offset +07:00

### Flow ประตู กับ flow ที่นั่ง (ห้ามปน)

**ประตู (Kiosk)**

1. เครื่องประตูส่ง `X-Kiosk-Key` ของห้องนั้น
2. คนสแกนหน้า หรือกรอกรหัส OTP ที่ขอจากเว็บ
3. ระบบตรวจว่าห้องเปิด, บัญชียังใช้ได้, และมีสิทธิ์อย่างน้อยหนึ่งข้อ:
   - มีตารางเรียนของวันนี้ตามเวลากรุงเทพ ในห้องนี้ ช่วง `[StartTime, EndTime)`
   - หรือมีการจองสถานะ Confirmed ที่กำลังอยู่ในช่วงเวลา (เจ้าของจอง หรือสมาชิกกลุ่มที่รับคำเชิญแล้ว)
4. ผ่าน → เขียน `access_logs` ว่า granted แล้วบอกให้เดินเข้าไปเลือกเครื่องว่าง
5. ไม่ผ่าน → denied พร้อมเหตุผล **ที่นั่งไม่เปลี่ยนสถานะ**

**ที่นั่ง (Windows Agent)**

1. เปิด Agent ด้วยสิทธิ์ Administrator บนเครื่องนั้น
2. ล็อกอินบัญชี KINOF (รหัสผ่าน + OTP อีเมลของล็อกอิน ไม่ใช่รหัสฉุกเฉินประตู)
3. ที่นั่งของเครื่องนั้นเป็น Occupied และมี session จาก `agent_logs` ประเภท `login`
4. ว่างเมื่อกด “ออกจากระบบเครื่องนี้” บน Agent หรือผู้ดูแลสั่งออกจากระบบตอน Agent ออนไลน์

สูตรที่ใช้อยู่: **ไม่ต้องสแกนประตูก่อนถึงจะล็อกอินเครื่องได้** การล็อกอินเครื่องในโค้ดตรวจแค่ว่าห้องเปิด และเครื่องยังไม่มีคนอื่นนั่ง ไม่ได้บังคับว่าต้องมีตารางเรียน/การจองก่อนนั่ง — สิทธิ์ตารางเรียน/จองใช้ที่ประตู

### เครื่อง Kiosk

เปิดจาก **จัดการข้อมูล → ห้องแล็บ** คัดลอกลิงก์เครื่องประตู หรือครั้งแรก:

`http://localhost:5173/kiosk/{roomId}?key=dev-kiosk-key-1`

คีย์ถูกเก็บใน `localStorage` ของเบราว์เซอร์นั้น แล้วตัดออกจาก URL จอสแกนไม่มีช่องให้คนทั่วไปกรอกคีย์ เปิดตั้งค่าใหม่ด้วย `?setup=1`

### เครื่องนั่งทำงาน

ไม่มี URL เว็บ เปิด `windows-agent` ด้วย `dotnet run` ใน PowerShell ที่ Run as administrator มีหน้าต่างล็อกอิน WinForms ปิดหน้าต่างแล้วยังอยู่ที่ถาดระบบ

## 4. Flow สำคัญทีละขั้น

### 4.1 สมัครและลงทะเบียนหน้า

1. เปิด http://localhost:5173/register
2. เลือกประเภทนักศึกษา (กรอกรหัส 10 หลัก) หรือบุคคลภายนอก
3. ตั้ง username / อีเมล / รหัสผ่าน (อย่างน้อย 8 ตัว)
4. ระบบสร้างบัญชีสถานะ Active ทันที แล้วส่ง OTP ยืนยันอีเมล
5. กรอก OTP ที่ `/login/otp`
6. ถ้ายังไม่มีใบหน้า จะถูกพาไป `/register/face`
7. ต้องรัน Face Service ที่พอร์ต 8001
8. จัดใบหน้าให้อยู่กลางกรอบ กระพริบตา ระบบถ่าย JPEG ส่ง `POST /api/auth/register/face`
9. Backend ส่งภาพในหน่วยความจำไป InsightFace ได้ embedding 512 มิติ เก็บใน `face_embeddings` **ไม่เก็บไฟล์รูป**

### 4.2 จองห้อง เชิญเพื่อน และคะแนนต่ำกว่า 50

1. Login นักศึกษา → จองห้องแล็บ
2. เลือกวัน–เวลา (ห้ามย้อนหลัง) ระบบเรียก `GET /api/rooms/available`
3. ห้องที่ชนตารางเรียนทั้งท่อน **ไม่โชว์ว่าง** — บล็อกทั้งรอบ ไม่ตัดเวลาเหลือหลังเลิกเรียน
4. ที่ว่างคิดจาก **จำนวนคน (headcount)** ไม่ใช่ “มีจองแล้วห้องเต็ม”
   - จองคนเดียว นับ 1
   - จองกลุ่ม นับเจ้าของ + สมาชิกในกลุ่ม + คำเชิญที่ยังรอตอบ (อย่างน้อย 1)
   - เชิญเพื่อนได้สูงสุด 4 คน (ทั้งปาร์ตี้ไม่เกิน 5)
5. ถ้าคะแนนพฤติกรรมเดือนนี้ต่ำกว่า 50 จองไม่ได้ ทั้งบนเว็บและที่ `POST /api/bookings` (HTTP 403)
6. เพื่อนที่เชิญต้องมีบัญชีในระบบแล้ว
7. มีเพื่อน → การจองเริ่มเป็น `Pending` ระบบส่งอีเมลคำเชิญหลังจองถูกบันทึก
8. เพื่อนเข้าเมนูคำเชิญ กดยอมรับหรือปฏิเสธ
9. ผู้จองกดยืนยันเมื่อทุกคนตอบรับแล้ว จึงเป็น `Confirmed`
10. คนที่อยู่ในกลุ่มที่ยืนยันแล้ว มีสิทธิ์เข้าประตูห้องนั้นในช่วงเวลาจอง

ถ้าส่งเมลคำเชิญไม่สำเร็จ การจองยังถูกสร้าง เพื่อนยังเห็นในแอป แต่ API ตอบ 503

### 4.3 เข้าประตูด้วยใบหน้า หรือ OTP ฉุกเฉิน

**ทางหลัก — ใบหน้า**

1. ต้องมีตารางเรียนหรือการจอง Confirmed ในช่วงเวลานั้น
2. เปิดหน้า Kiosk ของห้องนั้นพร้อมคีย์เครื่อง
3. กดสแกนใบหน้า มองกล้องนิ่งประมาณ 1.5 วินาที (ไม่ต้องกระพริบตา) หรือกดถ่ายเอง
4. ภาพไป `POST /api/kiosk/entry/verify-face`
5. Face Service สร้าง embedding → API จัดอันดับ cosine กับใบหน้าที่ลงทะเบียน
6. ผู้ที่ผ่านเกณฑ์ (คะแนน ≥ 0.5) ถูกกรองว่ามีสิทธิ์เข้าห้องนี้หรือไม่
7. ถ้ามีสิทธิ์คนเดียว ใช้คนนั้น ถ้ามีหลายคน ต้องห่างกันอย่างน้อยประมาณ 0.08 มิฉะนั้นถือว่ากำกวม
8. ผ่าน → จอขึ้น “เข้าห้องได้” พร้อมข้อความให้ไปเลือกเครื่องว่าง แล้วล็อกอินที่ Agent
9. ไม่ผ่าน 3 ครั้ง หรือระบบแนะนำ OTP → ไปหน้ากรอกรหัส
10. รู้จักหน้าแต่ไม่มีสิทธิ์ → หน้า denied เต็มจอ ไม่ดันไป OTP
11. สแกนหน้าล้มเหลว 5 ครั้งใน 15 นาทีต่อห้อง จะโดน 429 (แยกจากโควตา OTP ของห้องเดียวกัน)

**ทางสำรอง — OTP ฉุกเฉิน**

1. บนเว็บที่ล็อกอินแล้ว ไป “รหัสเข้าห้อง”
2. ขอรหัส (ผูกห้องได้) ส่งไปอีเมล หมดอายุ 10 นาที ใช้ครั้งเดียว
3. โควตา: **เดือนละ 5 ครั้ง** และ **ชั่วโมงละ 3 ครั้ง**
4. กรอก 6 หลักที่ Kiosk เท่านั้น **ห้ามเอาไปพิมพ์เป็นรหัสผ่านเครื่อง Agent**
5. รหัสผิด 5 ครั้ง / 15 นาที ต่อห้อง โดน 429
6. รหัสถูกแต่ไม่มีสิทธิ์เข้า → denied (รหัสถูกทำเครื่องหมายใช้แล้วก่อนตรวจสิทธิ์)

### 4.4 นั่งคอมพิวเตอร์

1. Backend ต้องเปิดที่ 5106 ก่อน
2. เปิด PowerShell **Run as administrator**
3. `cd windows-agent` แล้วตรวจ `appsettings.json`: `ApiBaseUrl` = `http://localhost:5106`, `ApiKey` = `dev-agent-key-1`
4. `dotnet run` — รอบนี้ไม่ติดตั้งเป็น Windows Service เพราะต้องมีหน้าต่างล็อกอิน
5. กรอกบัญชี KINOF + OTP อีเมลล็อกอิน (ชุดเดียวกับเว็บ ไม่ใช่รหัสประตู)
6. สำเร็จ → `seats.status = Occupied`
7. ปิดหน้าต่างหรือย่อ โปรแกรมยังทำงานที่ถาดระบบ ที่นั่งยัง Occupied

ถ้า Agent อยู่ใน VMware NAT อย่าใช้ `localhost` ใน VM ให้ชี้ IP โฮสต์ และให้ API ฟัง `0.0.0.0:5106`

### 4.5 ออกจากระบบที่นั่ง กับ ออกจากเว็บ

| การกระทำ | ที่นั่ง | เซสชันเว็บ |
|----------|--------|-------------|
| ปุ่มออกจากระบบบนเว็บ (Sidebar) | **ไม่เปลี่ยน** | ล้าง JWT |
| ปุ่ม “ออกจากระบบเครื่องนี้” บน Agent | เป็น Available | ไม่เกี่ยว |
| แอดมินกดสั่งออกจากระบบใน Tracking ตอน Agent ออนไลน์ | ว่าง และ Agent ได้รับคำสั่งออก | ไม่เกี่ยว |
| แอดมินสั่งตอน Agent ออฟไลน์ | **ทำไม่ได้** (409) | — |
| เครื่องยังไม่มี Agent ติดตั้ง | แอดมินปล่อย Occupied จากเซิร์ฟเวอร์ได้ | — |
| ปิดหน้าต่าง Agent / ปิดแท็บเว็บ | ที่นั่งยัง Occupied | แท็บเว็บหลุดตามเบราว์เซอร์ |

ไม่มีปุ่มออกจากห้องบนจอ Kiosk

### 4.6 แอดมิน Monitor

หน้า Monitor ค้นได้ และฟอร์มเพิ่มรายการติดด้านบน ไม่เลื่อนหายไปกับตาราง

**บล็อกเว็บ**

- เพิ่มโดเมนเอง เช่น `facebook.com` เข้า `website_blacklist` (`source = manual`)
- หรือเลือกหมวด UT1 แล้วกดนำเข้า ค่าเริ่มต้น 250 ต่อหมวด สูงสุด 400 ไม่เททั้งคลังหลายหมื่นโดเมน
- ลบหมวดจะลบเฉพาะแถว `source = ut1` ของหมวดนั้น ไม่ลบโดเมนที่แอดมินพิมพ์เอง
- Agent ซิงค์รายการประมาณทุก 2 นาที แล้วเขียนเฉพาะช่วง `# KINOF-BLOCK-START` … `# KINOF-BLOCK-END` ใน hosts

**บล็อกโปรแกรม**

- ใส่ชื่อ process เช่น `steam.exe`
- Agent สแกนประมาณทุก 3 วินาที ชื่อตรงแล้วปิดเฉพาะ process นั้น
- ไม่ปิดเครื่อง ไม่ปิดตัว Agent ไม่ปิด process ระบบ Windows
- เมื่อบล็อกได้ จะส่ง log `program` ที่น่าสงสัยขึ้นคิวรอแอดมิน

**อนุญาตโปรแกรม + ของไม่รู้จัก**

- Allowlist เป็นรายการซอฟต์แวร์แล็บ (Chrome, VS Code, Office, Python ฯลฯ)
- โปรแกรมที่ไม่ใช่ระบบ Windows ไม่ใช่ allowlist และไม่ใช่ blacklist จะถูกรวมเป็น event `unknown_program`
- แท็บ **ไม่รู้จัก** โชว์สรุปจำนวนครั้ง/จำนวนเครื่อง **ไม่ขึ้นคิวทีละแถว และไม่หักคะแนน**

**น่าสงสัย**

- กด **ดี (ผ่าน)** → ไม่หัก ไม่บล็อก
- กด **แย่ (บล็อก)** → ใส่รายการบล็อก แล้วหัก 5 จากผู้ใช้คนนั้นถ้าผูก user ได้

Discord เป็นตัวอย่างที่ทีมเคยชน: เอา `discord.exe` ออกจากบล็อกโปรแกรมแล้วยังเข้าเว็บไม่ได้ เพราะ `discord.com` / `discord.gg` อยู่ในหมวดโซเชียล UT1 และถูกเขียนลง hosts — ต้องลบโดเมนแล้วรอ Agent ซิงค์ hosts ด้วย

### 4.7 พฤติกรรม: หักคะแนน รีเดือน คิวรีวิว

- คะแนนต้นเดือน = 100
- หักเฉพาะแถวที่เกิดตั้งแต่ต้นเดือนกรุงเทพ คะแนนที่เหลือ = `max(0, 100 - ผลรวมที่หักเดือนนี้)`
- วันที่ 1 ของเดือนถัดไป คะแนนกลับไปนับใหม่โดยอัตโนมัติ
- ต่ำกว่า 50 จองห้องไม่ได้
- **ไม่มาตามจอง (no-show):** หลังหมดเวลาจอง Confirmed ถ้าคนในกลุ่มไม่ปรากฏทั้งใน `access_logs` granted ของห้องนั้น และไม่ปรากฏ login บน Agent ในห้องนั้นในช่วงนั้น → หัก 5 อัตโนมัติ
- **กิจกรรมที่ Agent จับได้:** ยังไม่หัก ขึ้นคิวจนกว่าแอดมินกดแย่ จึงหัก 5
- โปรแกรมไม่รู้จักไม่เข้าคิวนี้

เคยมีบั๊กที่เปิด API แล้วคะแนนและโควตา OTP ฉุกเฉินถูกล้างทุกครั้ง ตอนนี้รีเซ็ตครั้งเดียวในโหมด Development แล้วเขียนไฟล์ marker `App_Data/dev-reset-scores-otp.done`

## 5. ตาราง API สำคัญ (จัดกลุ่ม)

Base URL จริง: `http://localhost:5106`

- JWT = `Authorization: Bearer …`
- Agent = header `X-Agent-Key`
- Kiosk = header `X-Kiosk-Key` ของห้องนั้น

### Auth

`POST /api/auth/register` · `login` · `verify-email-otp` · `resend-email-otp` · `refresh` · `forgot-password` · `reset-password`

`GET /api/auth/me` · `POST /api/auth/register/face`

`POST /api/auth/entry-otp/request` · `resend` · `GET /api/auth/entry-otp/active`

### Booking / ห้อง / คำเชิญ

`GET /api/rooms` · `GET /api/rooms/available`

`GET /api/bookings/me` · `POST /api/bookings` · `GET /api/bookings/{id}/group-status` · `POST .../confirm` · `POST .../cancel-pending`

`GET /api/invitations/users` · `GET /api/invitations/me` · `POST .../accept` · `POST .../decline`

`GET /api/schedule/me`

### Kiosk (ไม่ใช้ JWT)

`GET /api/kiosk/rooms/{roomId}`

`POST /api/kiosk/entry/verify-otp`

`POST /api/kiosk/entry/verify-face`

สำเร็จคืน `granted`, ชื่อผู้ใช้, ห้อง, ข้อความให้ไปล็อกอินเครื่อง **ไม่มีเลขที่นั่ง**

### Agent (ไม่ใช้ JWT)

`POST /api/agent/register` · `heartbeat` · `logs`

`GET /api/agent/website-blacklist` · `program-blacklist` · `program-allowlist`

`POST /api/agent/session/login` · `verify-otp` · `resend-otp` · `logout`

### Admin tracking / Monitor / พฤติกรรม

`GET /api/admin/tracking/summary|rooms|seats|activity`

`POST /api/admin/tracking/seats/{seatId}/logout`

`GET/POST/DELETE /api/admin/tracking/website-blacklist` และนำเข้าหมวด UT1

`GET/POST/DELETE .../program-blacklist` · `program-allowlist` · `GET .../unknown-programs`

`GET /api/admin/behavior/reviews` · `POST .../clear` · `POST .../penalize`

`POST /api/admin/exports` · `GET/POST /api/admin/kiosk-devices` · `POST .../revoke`

`GET /api/behavior` · `GET /api/nav-badges`

เส้น Agent เก่าใน `docs/API.md` เช่น `GET /api/agent/config` และ header `X-Api-Key` **ไม่มีในโค้ด**

| `access_logs` | ผลตรวจประตู |

## 7. งานที่เสร็จแล้ว กับของที่ยังจำกัด

### เสร็จแล้วในรอบนี้

- Auth จริง + OTP อีเมล + รีเซ็ตรหัส + JWT refresh
- ลงทะเบียนหน้าและสแกนหน้าที่ประตู
- จองตามความจุคน เชิญเพื่อน อีเมลคำเชิญ ชนตารางเรียนแล้วบล็อกทั้งรอบ
- Kiosk ผูกห้องด้วย `X-Kiosk-Key` ไม่จ่ายที่นั่ง
- Agent ล็อกอินเครื่อง บล็อกเว็บด้วย hosts บล็อกโปรแกรม อนุญาตโปรแกรม สรุปของไม่รู้จัก
- คะแนนพฤติกรรมรายเดือน เกณฑ์จอง 50 คิวน่าสงสัย
- Tracking แยกเครื่องมีคนนั่ง กับคนที่นั่งโดยยังไม่มีจองช่วงนั้น
- Export Excel/CSV จาก `agent_logs` ตามวันที่กรุงเทพ
- นำเข้าหมวด UT1 แบบจำกัดจำนวน
- Sidebar ติดซ้ายทั้งจอ + ป้ายจำนวนค้าง

### ยังจำกัด / ยังไม่ทำในรอบนี้

- Agent ต้องรันด้วยผู้ใช้ Administrator ยังไม่เป็น Windows Service เพราะต้องมี UI
- UT1 ไม่เททั้งไฟล์ หมวดละประมาณ 250 โดเมน (สูงสุด 400)
- Discord พังได้ทั้งจาก `discord.exe` และจากโดเมนใน hosts
- Chrome/Edge ถ้าเปิด Secure DNS อาจเลี่ยง hosts ได้ ต้องปิดแล้ว `ipconfig /flushdns`
- Agent ไม่ได้บังคับสิทธิ์ตารางเรียนก่อนนั่งเครื่อง (บังคับที่ประตู)
- ยังไม่มี partial booking หลังเลิกเรียน
- CORS ยังอนุญาตแค่ localhost:5173
- SQLite ไม่ใช่คำตอบระยะยาวถ้ามีคนใช้พร้อมกันมาก
- เอกสารหลายไฟล์ยังไม่ตามนโยบายประตู/ที่นั่ง
- บนเครื่องนี้ Face Service เคยติดตั้งที่ Python 3.11 global ส่วน `.venv` ในโฟลเดอร์อาจยังว่าง — เครื่องใหม่ควรสร้าง venv ตามคู่มือ
- ยังไม่ได้ติดตั้ง Agent/Kiosk บนเครื่องแล็บจริง (นอก localhost)

## 9. รายการบั๊กที่แก้แล้ว (16–17 ก.ย. 2569)

### 9.1 จอง 1 คนแล้วห้องโชว์เต็มทั้งห้อง

- **อาการเดิม:** มีการจองเดียว ห้องหายจากรายการว่าง ทั้งที่ความจุยังเหลืออีกหลายสิบที่
- **สาเหตุ:** นับการจองแบบล็อกทั้งห้อง ไม่นับจำนวนคน
- **ผลหลังแก้:** นับหัวคนของแต่ละการจองที่ทับช่วงเวลา ห้องยังว่างถ้าความจุเหลือพอ

### 9.2 คะแนนต่ำยังจองได้

- **อาการเดิม:** คะแนนพฤติกรรมไม่ขวางการจอง
- **สาเหตุ:** ไม่มีเกณฑ์ที่ `POST /api/bookings`
- **ผลหลังแก้:** เหลือต่ำกว่า 50 ได้ 403 ทั้ง API และหน้าจองห้อง

### 9.3 เปิด API แล้วคะแนน / โควตา OTP รีเซ็ตทุกครั้ง

- **อาการเดิม:** รีสตาร์ท backend แล้วประวัติหักคะแนนและรหัสฉุกเฉินถูกล้าง

- **ผลหลังแก้:** ล้างครั้งเดียว แล้วเขียน `App_Data/dev-reset-scores-otp.done`

### 9.4 นาฬิกา Kiosk ทำให้กล้องรีเฟรชทุกวินาที

- **อาการเดิม:** นาฬิกาเดินแล้วกล้องกระพริบ/รีเมานต์
- **สาเหตุ:** state เวลาอยู่ที่คอมโพเนนต์เดียวกับกล้อง
- **ผลหลังแก้:** แยก `KioskClock` มี state ของตัวเอง

### 9.5 สแกนหน้าไม่ผ่านทั้งที่มีลงทะเบียน / หน้าใกล้กันจับผิดคน

- **อาการเดิม:** คนลงทะเบียนแล้วสแกนไม่ติด หรือระบบเลือกบัญชีที่หน้าคล้ายทั้งที่คนนั้นไม่มีสิทธิ์เข้าห้อง
- **สาเหตุ:** เลือกคะแนนสูงสุดทั้งระบบโดยไม่บังคับความห่างจากคนรอง และไม่กรองสิทธิ์เข้าห้องก่อน

- **ผลหลังแก้:** ออกจากเว็บแค่ล้าง JWT ที่นั่งเปลี่ยนเฉพาะ Agent logout หรือแอดมินสั่งออก

- **อาการเดิม:** ลบ `discord.exe` แล้วแอป/เว็บยังใช้ไม่ได้

## 10. ความเสี่ยงและของที่อย่าทำ

### อย่า commit / อย่ากระจาย

- `kinof.db` และไฟล์ `-wal` / `-shm`
- log เช่น `backend/api-run.log`, `face-service/face-run.log`
- `App_Data/` โดยเฉพาะรูป problem reports, แคช UT1, ไฟล์ marker รีเซ็ต
- รหัส SMTP / Resend API key — อยู่ที่ user-secrets เท่านั้น
- คีย์เครื่องจริงที่แอดมินสร้าง (โชว์ครั้งเดียว)
- `Jwt:Key` ใน `appsettings.json` เป็นคีย์ development **ต้องเปลี่ยนก่อนขึ้นของจริง**

### อย่าสับสน Kiosk กับ Agent

| | Kiosk | Agent |
|--|--------|--------|
| อยู่ที่ | ประตูห้อง | เครื่องนั่ง |
| Header | `X-Kiosk-Key` | `X-Agent-Key` |
| ผูกกับ | ห้อง | ที่นั่ง |
| คีย์ dev | `dev-kiosk-key-1` | `dev-agent-key-1` |
| ล็อกอินคน | ไม่มี JWT ผู้ใช้ | บัญชี KINOF + OTP ล็อกอิน |
| รหัสฉุกเฉินจากเว็บ | ใช้ที่นี่ | ใช้ไม่ได้ |
| ผลสำเร็จ | เข้าห้องได้ | ที่นั่ง Occupied |

### ความเสี่ยงตอนเดโม

- เปิด API ใน Development จะ seed / ซ่อมข้อมูลบางอย่าง
- hosts ของเครื่อง dev จะถูกเขียนจริง
- ถ้าลืมรัน as Administrator บล็อกเว็บจะไม่เขียน hosts
- Face Service ไม่ขึ้น = ทั้งลงทะเบียนหน้าและสแกนประตูพัง (OTP ฉุกเฉินยังใช้ได้)
- หนึ่งเบราว์เซอร์หนึ่งบัญชี

## 11. สรุปหนึ่งหน้าสำหรับพรีเซนต์ + คำถามที่เพื่อนควรถามถ้าจะต่องาน

### สรุปพรีเซนต์

KINOF เป็นระบบแล็บอัจฉริยะที่แยกสองด่านให้ขาด: **ประตูตรวจสิทธิ์** และ **เครื่องตรวจว่าใครนั่ง**. นักศึกษาจองห้องตามจำนวนคน ไม่ล็อกทั้งห้องเพราะมีจองคนเดียว และถ้าคะแนนพฤติกรรมเดือนนี้ต่ำกว่า 50 จะจองไม่ได้ คะแนนเริ่ม 100 หักเฉพาะเดือนปัจจุบัน รีเซ็ตทุกเดือน ที่ประตูสแกนใบหน้าด้วย InsightFace (cosine 512 มิติ เกณฑ์ 0.5 กันหน้าใกล้กันด้วยช่องว่างประมาณ 0.08 และเลือกคนที่มีสิทธิ์เข้าห้องนั้น) ถ้าสแกนไม่ติดใช้รหัส OTP จากเว็บที่ประตูเท่านั้น ไม่ใช่รหัสผ่านเครื่อง เมื่อเข้าห้องแล้วไปเลือกเครื่องว่าง เปิด Windows Agent ด้วยสิทธิ์แอดมิน ล็อกอินบัญชี KINOF ที่นั่งจึงเป็น Occupied ออกจากเว็บไม่คืนเครื่อง ผู้ดูแลใช้ Monitor บล็อกเว็บผ่านไฟล์ hosts (โดเมนที่ใส่เองบวกหมวด UT1 ที่นำเข้าจำกัดจำนวน) และปิดโปรแกรมตามชื่อ exe ของที่ไม่รู้จักสรุปรวม ไม่หักคะแนนจนกว่าแอดมินจะกดว่าแย่ในคิวเว็บ/โปรแกรมน่าสงสัย ระบบรันครบสี่บริการบนเครื่องเดียวได้แล้ว แต่ Agent ยังไม่เป็น Windows Service เอกสารบางไฟล์ยังพูดว่ารุ่นเก่าที่ Kiosk จ่ายที่นั่ง — อย่าใช้เอกสารนั้นอธิบายเดโม

### คำถามที่เพื่อนควรถามก่อนรับงานต่อ

1. ฐานบนเครื่องนี้ชื่อห้องเป็น `Lab A` หรือ `ห้องแล็บ 1` และ `roomId` ของ Kiosk ที่จะเดโมคืออันไหน
2. SMTP บนเครื่องนี้ส่งเมลจริงแล้วหรือยัง ถ้ายัง OTP ต้องดูจากหน้าเว็บ/console — อย่าไปขอรหัส SMTP ในกรุ๊ป
3. ไฟล์ hosts ของเครื่องเดโมถูกเขียนช่วง KINOF อยู่หรือไม่
4. ใบหน้าของบัญชี `student` บนเครื่องนี้ลงทะเบียนด้วยหน้าใคร
5. คะแนนเดือนนี้ของบัญชีเดโมเหลือเท่าไร ถ้าต่ำกว่า 50 จองไม่ได้เป็นของตั้งใจ
6. จะขึ้นของจริงเมื่อไร เพราะงานที่เหลือคือ HTTPS, CORS โดเมนจริง, Jwt:Key ใหม่, รหัส seed ใหม่ ไม่ใช่ฟีเจอร์จองห้องที่ยังไม่เสร็จ
7. ใครเป็นคนถือ user-secrets และห้าม commit อะไรบ้างก่อนพุช
8. นโยบาย “นั่งเครื่องได้โดยไม่สแกนประตูก่อน” ยังยึดอยู่หรือจะเปลี่ยนในรอบถัดไป เพราะตอนนี้โค้ด Agent ไม่ได้เช็คตารางเรียนตอนล็อกอินเครื่อง
